# 自留地 · 个人网站

一个纯静态的个人站：5 个页面，只用 HTML / CSS / JavaScript，没有框架、没有后端、没有数据库。
内容单独放在 `content/` 和 `photos/` 里，页面只负责显示。

---

## 一、怎么在本地打开

### 方式一：直接双击（最快）

双击根目录的 `index.html`，浏览器就会打开首页。

这种方式能正常看，因为所有内容都被预编译成了一个 JS 数据文件（`content/data.js`），
不需要向服务器请求任何东西。

> 注意：一定要双击根目录的 `index.html`，不要双击 `content/` 里面的文件。

### 方式二：起一个本地服务器（推荐，更接近真实环境）

在项目根目录打开终端，任选一条命令：

```bash
# 如果电脑装了 Python
python -m http.server 8000

# 如果装了 Node.js
npx serve .
```

然后浏览器访问 <http://localhost:8000>。

两种方式看到的效果基本一样。上传到网上之后，用的是同样的文件。

## 二、每个文件夹是干什么的

```
/
├─ index.html          首页（入口页）
├─ blog.html           博客列表
├─ updates.html        近况
├─ works.html          作品
├─ about.html          关于
│
├─ assets/
│  ├─ css/style.css    所有样式（配色、布局、字体都在这一个文件里）
│  ├─ js/main.js       所有脚本（渲染内容、灯箱、时钟）
│  ├─ js/comments.js   评论区逻辑（按需加载 Waline）
│  ├─ js/announcement.js 公告弹窗（打开页面时那个弹窗）
│  └─ favicon.svg      浏览器标签页上的小图标
│
├─ content/            ★ 内容层：你平时只需要动这里
│  ├─ posts/           博客文章，一篇一个 .md 文件
│  │  ├─ post-001.md
│  │  ├─ post-002.md
│  │  └─ ...
│  ├─ works/           作品条目，一个 .md 文件
│  │  ├─ work-004.md
│  │  └─ ...
│  ├─ updates/         近况，一条一个 .md 文件
│  │  ├─ update-001.md
│  │  └─ ...
│  ├─ announcements/   公告，一条一个 .md 文件（标 active 的那条会弹）
│  │  ├─ notice-001.md
│  │  └─ ...
│  ├─ about.md         关于页的文字和照片路径
│  ├─ quotes.js        首页「换一句」的歌词池
│  ├─ site-config.js   站点配置（评论功能在这里填）
│  └─ data.js          自动生成，不要手改
│
├─ photos/             所有上线用的图片（压缩后的 webp）
│  ├─ me-avatar-*.webp 那张头像（-thumb 小图 / -view 大图），首页和关于页都用它
│  └─ photo-01.svg     近况示例里的占位图，换成真照片后可以删
│
├─ raw/                ★ 原图暂存区：把要处理的照片丢这里（不进仓库）
├─ archive/            压完的原图挪到这里留底（不进仓库）
│
└─ tools/              辅助脚本，不影响网站本身
   ├─ build-content.js          把 md 转成 data.js
   ├─ compress-photos.js        把原图压成 webp（两档）
   ├─ build-content.cmd         ↑ 的双击启动器（不想开终端就用它）
   ├─ compress-photos.cmd       近况档的双击启动器
   ├─ compress-photos-work.cmd  作品档的双击启动器
   ├─ package.json              sharp 的依赖声明
   └─ make-placeholder-photos.js 重新生成示例图片
```

**核心原则**：页面（`.html`）不改，内容（`.md`）随时加。
这样你以后想调整排版，不会碰到文字；想加文章，也不会碰到代码。

## 三、怎么加内容

### 1. 新增一篇博客

在 `content/posts/` 里新建一个文件，比如 `post-004.md`，内容长这样：

```markdown
---
title: 这篇文章的标题
date: 2026-11-02
tag: 日常
summary: 一句话摘要，会显示在列表和正文开头，可以不写。
---

正文从这里开始，用普通的 Markdown 写就行。

可以分段。

## 可以用小标题

- 可以用列表
- **加粗**、*斜体*、`行内代码`
- 也可以用 [链接](https://example.com)

> 也可以用引用。
```

文件名的规则：`post-` 加三位数字，**不要重复**。
排序是按 `date` 倒序来的，跟文件名无关。

### 2. 新增一个作品

在 `content/works/` 里新建 `work-010.md`（编号随手往后排，别和已有的撞名）：

```markdown
---
title: 作品名字
year: 2026
status: 半成品
summary: 一句话说明这是什么。
link: https://可选的链接，没有就留空
cover: photos/work-010-01-view.webp
photos: photos/work-010-02-view.webp | 过程图, photos/work-010-03-view.webp
---

展开后看到的详细内容，随便写。正文里也能直接插图：

![](photos/work-010-04-view.webp)
```

`status` 建议只用这三个值，颜色会自动对应：

| status 填什么 | 标签颜色 |
| --- | --- |
| `已完成` | 荧光黄 |
| `半成品` | 橙色 |
| `烂尾` | 粉色 |

**两个图片字段的区别：**

- `cover` —— 卡片上那张封面，**只能一张**，不填就不显示封面。
- `photos` —— 点「展开看看」后弹出的框里的组图，用英文逗号分隔，每张后面可以跟 `| 图注`。
  点任意一张照片会再放大一层（灯箱），按 Esc 或点黑底关闭。
  图注里**不要用英文逗号**，会被当成分隔符。想放 10 张、20 张都行，会排成网格。

### 3. 发一条近况

一条近况 = `content/updates/` 里的一个 `.md` 文件，文件名照 `update-001.md` 往下排。
文字四五十字就够——那种「不值得单独写一篇博客」的事，放这里。

```markdown
---
date: 2026-10-12
place: 教学楼
photos: photos/2026-10-12-01-view.webp, photos/2026-10-12-02-view.webp | 图注可以不写
---

在楼道里耗了一下午。三点五十的光最好，消防栓上那点亮撑着整张照片。
```

三种发法，按需要删：

| 想发什么 | 怎么写 |
| --- | --- |
| 文字 + 图片 | 正文写话，`photos:` 填图 |
| **只有文字** | 把 `photos:` 整行删掉 |
| **只有图片** | 正文留空（`---` 之后什么都不写） |

- `place` 是可选的，出现会显示在日期右边。
- 图片写 `-view.webp` 那个文件名，缩略图会自动换上，不用写两行。
- 照片先压缩：原图丢进 `raw/` → `node tools/compress-photos.js` → 复制生成的文件名。
  具体见第 5 小节。
- 排序按 `date` 倒序，跟文件名无关。

### 4. 改关于页

直接编辑 `content/about.md`。开头那几行里的 `photo:` 指向照片路径，
换照片就把新图片放进 `photos/`，然后改这里的文件名。

### 5. 照片怎么压（第一次用看这里）

相机和手机的原图一张 3–8MB，直接放进网站，一个近况页就能让朋友在手机上
等半分钟，几百张还会撑爆托管空间。所以原图永远不进仓库，只放压缩后的版本。

**先装一次依赖**（只在第一次做，或者换了电脑之后）：

```bash
cd tools
npm install
cd ..
```

**然后按照片类型选一档**：

```bash
node tools/compress-photos.js          # 近况档：手机照片，展示图长边 1600
node tools/compress-photos.js --work   # 作品档：相机照片，展示图长边 2400
```

**不想开终端？`tools/` 里有三个双击就能用的启动器**：

| 双击这个 | 作用 |
|---|---|
| `tools/compress-photos.cmd` | 压 `raw/` 里的照片（近况档） |
| `tools/compress-photos-work.cmd` | 压 `raw/` 里的照片（作品档） |
| `tools/build-content.cmd` | 改完 md 之后跑构建 |

启动器会自己去找 Node，顺序是：`C:\Program Files\nodejs` → `C:\Program Files (x86)\nodejs`
→ `%LOCALAPPDATA%\Programs\nodejs` → WorkBuddy 自带的运行时
（`%USERPROFILE%\.workbuddy\binaries\node\`）→ 最后才看系统 PATH。
运行时它会打印 `[1]`～`[5]` 五步标记，走完最后一句是 `[5] done, exit code 0`。

**如果双击后卡住不动**，看它停在哪一步：这些标记同时会写进 `tools\_run.log`。
把那个文件发我就能定位（这个文件只是诊断用，随时可以删）。

**完全不想碰启动器**，就打开终端粘这一行（路径照抄，含引号）：

```
"C:\Users\Manuel\.workbuddy\binaries\node\versions\22.22.2-6\node.exe" "C:\Users\Manuel\WorkBuddy\2026-10-17-20-02-25\tools\compress-photos.js"
```

最后那个参数换成 `--work` 是作品档，换成 `build-content.js` 是构建。

**千万别双击 `.js` 文件**。Windows 把 `.js` 默认关联到「Windows 脚本宿主」，
双击会弹一个「无效字符 / 800A03F6」的报错框 —— 那不是脚本坏了，是打开方式错了。
`.js` 只能交给 Node 跑（也就是上面那些命令，或者那几个 `.cmd`）。

| | 缩略图 | 展示图 | 一张大约占 |
|---|---|---|---|
| 近况档 | 长边 800px / q78 | 长边 1600px / q84 | 0.35–0.45 MB |
| 作品档 | 长边 800px / q80 | 长边 2400px / q86 | 0.6–0.9 MB |

**想知道现在占了多少、还能放多少张**：

```bash
node tools/compress-photos.js --check
```

它会列出 `photos/` 的总大小、体积最大的几个文件，以及按 GitHub Pages
1GB 上限还能放多少张。**到 80% 就该下手清理了**，清理的动作就是：
把 `content/updates/` 里对应的 .md 删掉、再删掉 `photos/` 里那两张 webp。

**几个坑**：

- **HEIC 解不了**。iPhone 默认存 HEIC，先在「设置 → 相机 → 格式」改成
  「兼容性最佳」，或者导出成 JPG 再放进来。
- **别二次压缩**。微信、相册 App 转发一次就已经压过一遍了，拿那个再压，
  画质会有明显发糊。永远从原图转。
- **同一批照片别混着两档压**。近况用近况档、作品用作品档，混用会让
  `srcset` 里的尺寸声明对不上，浏览器会挑错版本。

### 6. 发一条公告（打开网站时弹出来的那个）

公告放在 `content/announcements/`，**一条公告一个 `.md` 文件**，文件名建议
`notice-001.md`、`notice-002.md` 这样排下去。改完跑一次构建，全站生效。

```markdown
---
active: true
id: notice-002
title: 十一月起相册改成按月整理了
date: 2026-11-01
tone: normal
---

正文随便写，支持**粗体**、列表、链接。
```

| 字段 | 作用 |
| --- | --- |
| `active` | `true` 才会弹窗。**同一时间只该有一条是 `true`**；标了两条以上，只会弹日期最新的那条 |
| `id` | **公告的版本号**。访客关掉后浏览器会记住这个值；换成新的，所有人下次来都会再看到 |
| `title` | 弹窗标题，一两句话说清重点 |
| `date` | 显示在右上角，写成 `2026-11-01` 就行 |
| `tone` | 默认荧光黄；填 `alert` 变成橘红色，用于「这条比较重要」 |

**公告有存档，发过的不会消失。** 所有公告（不管是不是 `active`）都会列在
近况页顶部的「站点公告」里，默认收起，点开能看全部历史。所以日常只需要这样做：

| 你想做的事 | 怎么做 |
| --- | --- |
| 发一条新公告 | 新建 `notice-002.md` 写内容标 `active: true`，**同时把旧的 `notice-001.md` 的 `active` 改成 `false`** |
| 不想再弹，但想留着 | 只把 `active` 改成 `false`，它还在存档里 |
| 彻底不要这条 | 删掉那个 `.md` 文件 |

**它是怎么弹的**（这些行为都是有意的，改之前先想清楚）：

- 打开任意页面时弹，**不是**每个页面都弹一次
- **同一则公告每人只弹一次**：关掉后记在浏览器本地，以后都不再打扰
- 没点关闭就刷新、或者开新标签页去看别的页面，也**不会**再弹
  （额外记了一个时间戳，12 小时内只自动弹一次，免得每翻一页糊一次）
- 从分享链接带 `#` 锚点进来的（比如某篇文章），不弹，免得挡住正文
- `Esc`、点遮罩、右上角 `×`、底部「知道了」四种关法都行
- 浏览器存不住这些记录时（无痕模式、直接双击本地 html 文件），会退一步记在标签页上：
  **同一个标签页里翻页不会重复弹**，关掉标签页就忘了（下次进来再弹一次）
- 关掉之后想再看：页脚有一行小字「公告」；有两条以上时，弹窗底部还会多一个
  「看全部 N 条公告 →」，点了直接跳到近况页的存档（存档会自动展开）

> 公告弹窗用的是浏览器原生的 `<dialog>`，没有引任何库；它也只在能用的浏览器上弹，
> 老浏览器直接跳过，不会报错。

### 7. 改首页那句歌词

首页大字下面那行字，点「换一句」会按顺序往下换。句子全部在 `content/quotes.js` 里，
一条长这样：

```js
{ text: '天空好想下雨 我好想住你隔壁', from: '《有何不可》' },
```

- `text` —— 上面那行歌词。
- `from` —— 下面那行小字的出处。不想显示就写 `from: ''`，那行会自动消失。
- 顺序就是点「换一句」的顺序，走到最后回到第一条。
- 想加句子就在数组里加一行，注意**上一行结尾的逗号别漏**。

改完存盘，刷新页面就生效（这个文件不需要跑构建脚本）。

### 8. 改跑马灯上那串字

首页那条黄底的横向滑动字，写在 `index.html` 的 `<div class="marquee-track">` 里，**一个字都没有硬编码进脚本**。

有个地方容易踩：那串 `<span>` **原样复制了 4 份**，不是写错了。动画只把整条轨道往左推「一份」的距离（CSS 里 `translateX(-25%)`），推到尽头时第 2 份正好落在第 1 份原来的位置，接缝看不出来。所以：

- **改词只改第一行**，然后把它复制三遍覆盖下面三行，四份必须一模一样。
- 份数要是改了（比如加到 5 份），`assets/css/style.css` 里的 `translateX(-25%)` 要跟着改成 `100 ÷ 份数`，否则会错位或右边露空档。
- 少于 4 份不行：剩下的份数铺不满那条，右边会露出黄底空档。
- 速度看第 11 节 `.marquee-track` 的 `animation ... 13s`，调大更慢、调小更快。

## 四、内容什么时候生效（重要）

**改完 `.md` 文件后，要跑一次构建命令**，页面才会显示新内容：

```bash
node tools/build-content.js
```

看到这样的输出就说明成功了：

```
内容构建完成：
  博客 3 篇
  近况 3 条
  作品 3 个
  公告 1 条，当前弹「这个站刚搭好」
  关于页 已生成
  输出 → content\data.js
```

然后再刷新浏览器。

如果电脑上没装 Node.js，也可以直接跟 AI 说「帮我跑一下内容构建」，让它代劳。

> 为什么需要这一步？
> 浏览器双击打开本地文件时不允许用 `fetch` 读 `.md`，但允许加载 `.js`。
> 所以用一个几十行的小脚本，把 Markdown 预先翻译成 `content/data.js`，
> 页面读这个文件就行。`data.js` 是自动生成的，**千万不要手改**，
> 下次构建会把它覆盖掉。

### 改完没反应？按这个顺序查

1. **构建跑了没**：`node tools/build-content.js`，或者双击 `tools/build-content.cmd`。
   看那行数字有没有变，没变就是文件没被读到（目录/后缀写错了）。
2. **卡片标题变成了 `work-004` 这种文件名** → 文件头没读出来。第一行必须是三条减号 `---`，
   前面不能有空行。有编辑器（或者从聊天窗口复制过来）会把减号**转义成 `\---`**，行尾还多两个空格；
   构建脚本现在会把这种写法认回去，并且会打一行提醒，但最好还是手动改成干净的 `---`。
3. **图裂了**：路径要写全 `photos/xxx-view.webp`，不能只写文件名。构建时会检查盘上有没有这个文件，
   缺了会打 `!` 提醒。
4. **作品/近况的图少了几张**：`photos:` 那一行**必须写在一行里**，用英文逗号分隔。
   换行的话第二行会被当成一句正文，图就丢了。
5. **`---` 那行出现在正文里**：说明文件头提前闭合了（多半是前面多了一个 `---`），删掉多余的即可。

## 五、想改样式，从哪里下手

全部在 `assets/css/style.css`，文件开头有一段变量：

```css
:root {
  --ink: #111111;      /* 主色：文字、边框 */
  --paper: #f3efe7;    /* 底色 */
  --hot: #ff3b00;      /* 强调色 1：橙红 */
  --volt: #d6ff00;     /* 强调色 2：荧光黄 */
  --cyan: #00c2b2;     /* 强调色 3：青 */
  --pink: #ff2e93;     /* 强调色 4：品红 */
  --bw: 3px;           /* 全局边框粗细 */
}
```

**只改这几行，整个站的性格就变了。** 比如：

- 想更克制：把 `--volt` 换成 `#eeeeee`，`--bw` 改成 `2px`
- 想更凶：把 `--bw` 改成 `5px`，`--hot` 换成 `#0000ff`
- 想换底色：`--paper` 换成 `#ffffff` 就是干净白底

CSS 文件里每个大区块前面都有中文注释（`05 首页`、`07 近况、图片与灯箱`……），
想改哪一块，直接跳到那个编号。

代码里的中文注释只是说明用途，删掉不影响运行，但建议留着。

## 六、部署到 GitHub Pages

只写步骤，实际部署时按这个顺序做。

**1. 建仓库**

在 GitHub 上新建一个仓库，名字随意（比如 `my-site`）。选 **Public**。

> 如果想让网址是 `https://你的用户名.github.io`，仓库名必须写成 `你的用户名.github.io`。
> 如果仓库名是别的，网址会变成 `https://你的用户名.github.io/仓库名/`。

**2. 上传文件**

把根目录下的 **所有文件和文件夹** 一起上传，注意保持目录结构不变
（`assets/`、`content/`、`photos/` 必须是顶层文件夹，不能只传 HTML）。

**3. 开启 Pages**

仓库页 → `Settings` → 左侧 `Pages` →
`Source` 选 `Deploy from a branch` → 分支选 `main`，目录选 `/ (root)` → `Save`。

**4. 等 1–2 分钟**

页面上方会出现网址，形如 `https://用户名.github.io/仓库名/`。打开检查一下。

**5. 以后更新**

改完内容、跑完 `node tools/build-content.js`，把 `content/data.js` 一起提交上去，
一两分钟后线上就会更新。

**常见失败原因**：只传了 HTML 没传 `assets/`，导致页面没有任何样式；
或者分支名不是 `main`。

## 七、部署到 Cloudflare Pages

**1.** 登录 Cloudflare → 左侧 `Workers & Pages` → `Create` → `Pages` → `Connect to Git`。

**2.** 授权并选择你的仓库。

**3.** 构建设置：

- Framework preset：`None`
- Build command：**留空**
- Build output directory：`/`（有的界面要求填 `.`）

**4.** 点 `Save and Deploy`，一两分钟后拿到 `https://xxx.pages.dev` 网址。

**5.** 之后每次往仓库 push，会自动重新部署。

> 注意：Cloudflare Pages 不会自动执行 `node tools/build-content.js`。
> 如果你习惯在本地改完再上传，就没事；如果想让它在云端自动构建，
> 把 Build command 改成 `node tools/build-content.js`（此时脚本的输出文件
> `content/data.js` 需要在构建后被保留，这一点后续需要额外配置）。
> **第一版建议：本地构建好再上传，最省事。**

## 九、这一版没做的事（不是 bug，是留白）

- 博客和作品是**折叠展开**，没有独立详情页。好处是简单、双击就能用；
  代价是单篇文章的分享链接长这样：`blog.html#post-002`（能用，但不够漂亮）。
- 没有分页、搜索、标签筛选。文章上百篇以后需要再加。
- 近况没有分页、没有按年月归档，条数一多会变成一条很长的流。
- 没有 RSS、没有访问统计（评论已经接上了，见第十节）。
- 图片不会自动压缩，**要自己跑 `node tools/compress-photos.js`**（见第三节第 5 小节）。
  原图放在 `raw/`，压完的原图进 `archive/`，两个文件夹都不进仓库。
- 公告**同时只有一条**会弹窗（标 `active: true` 的那条），没有排队弹出。
  同一时间只跟访客说一件事，这是故意的。历史公告不会丢，都在近况页的
  「站点公告」存档里，但那里没有分页 —— 攒到几十条会很长。

## 十、开启评论（Waline）

博客文章和每条近况下面都有一个「留言」区块，默认收起，而且**还没有启用**——
点开会看到一句提示。启用它需要自己部署一个很小的评论服务，大约 20–30 分钟，不需要写代码。

先理解两件事：

1. **访客只能留言，不能改你的网站内容。** 这是静态站的天然属性——线上文件只有你能改，
   访客拿到的是一份副本。留言之所以能存在，是因为它被写进了数据库，而不是写进你的网页文件。
2. **评论服务是一个独立的小网站**，跟你的站点分开部署。你部署一次，所有页面共用它。

### 为什么选 Waline

你的访客是朋友和家人。如果评论系统要求对方先注册账号（比如 GitHub），现实中
**大概率一条留言都不会有**——大家不会为了说一句“照片好看”去注册账号。
Waline 只填个昵称就能留言，代价是你多部署一个服务、偶尔去后台删垃圾评论。

### 第 1 步：部署评论服务

打开这个一键部署地址（Vercel 官方的模板克隆页）：

<https://vercel.com/new/clone?repository-url=https%3A%2F%2Fgithub.com%2Fwalinejs%2Fwaline%2Ftree%2Fmain%2Fexample>

用 GitHub 账号登录 → 输入项目名（例如 `my-waline`）→ `Create` → 等一两分钟。

### 第 2 步：连一个数据库

Vercel 项目页 → 顶部 `Storage` → `Create Database` → 提供商选 `Neon` → 一路 `Continue`
（地域选离你近的，其它不用改）。

创建好之后点 `Open in Neon` → 左侧 `SQL Editor` → 把
<https://github.com/walinejs/waline/blob/main/assets/waline.pgsql>
里的 SQL 全部复制粘贴进去 → `Run`。这一步是建表，不做的话后面留言会报错。

### 第 3 步：重新部署

回到 Vercel → 顶部 `Deployments` → 最新一条右侧 `Redeploy`。
**这一步不能省**，它的作用是让刚连上的数据库真正生效。

### 第 4 步：拿到服务地址

`Overview` 页里点 `Visit`，打开的那个域名就是你的 `serverURL`，
形如 `https://my-waline.vercel.app`。记下来，下一步要用。

### 第 5 步：填进配置文件

打开 `content/site-config.js`，只改一个值：

```js
window.SITE_COMMENTS = {
  serverURL: 'https://my-waline.vercel.app', // ← 换成你自己的地址，末尾不要加 /
  lang: 'zh-CN',
  allowImageUpload: false,
  emoji: false
};
```

保存、刷新，展开任意一篇文章的「留言」，看到输入框就成功了。

### 第 6 步：把自己设成管理员

打开 `<你的地址>/ui/register` 注册一个账号——**第一个注册的人自动成为管理员**。
以后想删评论、看留言量，进 `<你的地址>/ui` 就行。

### 几个要知道的限制

- **评论存在你的数据库里，不在网页文件里**，所以访客永远改不了你的文章。
  这是两件事，不存在“能留言就能发文章”。
- **必须联网才显示评论区**：客户端是从 CDN 加载的。网站其它部分仍然断网可看。
- **本地双击也能留言**（Waline 不校验域名），只是第一次需要联网下载组件；
  如果双击后评论区一直转圈，改用本地服务器打开（第一节方式二）再看。
- **图片上传默认关闭**。Waline 默认把图片转成 Base64 存进数据库，几张手机原图
  就能把免费额度吃掉，留言列表也会变卡。要开就改 `allowImageUpload: true`，
  更好的做法是接一个图床（属于进阶内容，先不折腾）。
- **表情默认关闭**，同样是为了少几个外部请求；改成 `emoji: true` 会加载微博表情。
- **防垃圾**：后台能删评论、标记、封禁。个人站被扫到的概率不高，看到垃圾清掉就行。
- **免费额度**以 Vercel / Neon 当期政策为准 ⏳，个人站的量级基本用不完。
- **想换评论系统**：只需要重写 `assets/js/comments.js` 一个文件，
  页面结构和 CSS 都不用动——当初就是特意把评论逻辑隔开的。
- **安全提醒**：评论是别人写的字，永远不要把评论内容直接用 `innerHTML` 塞进页面。
  Waline 自己会转义，但你以后写任何插件都要守住这一条，这是 XSS 最常见的入口。
